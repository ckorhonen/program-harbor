# Eight-minute demo journey

1. Start at the launchpad and choose **Admin demo**. The dashboard opens on `AI Engineer Sandbox Summit`, showing accepted speakers, missing files, overdue tasks, two deliberate conflicts, and one unscheduled session.
2. Open **Forms**, add or edit the `Session format` field, and confirm the workshop-only `Hands-on requirements` rule in the live preview. Publish the version and open the public CFP.
3. Submit a workshop proposal as a public user with a co-speaker. The server validates the conditional field and routes the proposal to the Security review plan; the submission appears in the admin queue without a refresh.
4. Switch to **Evaluator demo**, score the assigned proposal across the visible rubric, and save. Return to submissions, accept it, and show that the speaker/session records were created.
5. Open **Speaker demo**. Update the bio, upload a headshot/slides, and complete the “Speaker details” form. Keep the admin dashboard open in another tab so the onboarding count moves within five seconds.
6. Open **Schedule**, place the accepted session in a room/time, intentionally trigger the seeded speaker or room conflict, and resolve it or record an intentional override. Move the session again and reload to prove persistence.
7. Open the session drawer, preview the schedule-confirmation message, download the ICS, and run an Accelevents dry-run. The UI should show local emulator status if no live credentials exist.
8. Finish on the public speaker gallery and schedule, then show the API docs and the **Reset demo** control. The reset confirmation explains that only the dedicated demo namespace will be replaced.
